## 一句话定义

声明式编程是**只描述“想要什么结果”，把“怎么做到”交给底层引擎**的编程方式——就像点外卖只写“一份宫保鸡丁”，不用教厨师怎么炒。

## 为什么重要

- **代码更短、意图更清楚**：一行 SQL 可以替代几十行循环 + 字典。
- **引擎可以替你优化**：数据库会选择索引，Polars 会重排查询，Kubernetes 会自己调度容器——你写的“期望”不变，执行方式可以越来越好。
- **现代基础设施全是声明式的**：SQL、HTML/CSS、正则、Docker Compose、Kubernetes YAML、Terraform、GitHub Actions……

## 原理 / 图解

声明式 = **描述（What）** + **执行器（How，由别人写好）**。

```mermaid
flowchart LR
    U[你写的描述<br/>SQL 或 YAML 或正则] --> E[引擎<br/>解析器加优化器]
    E --> P[执行计划<br/>选索引 排顺序 并行]
    P --> R[结果]
    E -.可替换升级.-> P
```

一种常见的声明式模式是 **“期望状态 vs 当前状态”对账（reconcile）**：你只声明“web 要 3 个实例”，控制器不断比较现实与期望，自动补差。【有据可查】Kubernetes 文档对“声明式对象管理”的说明：<https://kubernetes.io/docs/concepts/overview/working-with-objects/object-management/>

## 可运行示例

三个小例子：SQL、正则、期望状态对账（Python 3.15.0 实际运行）：

```python
# 文件：examples/03_declarative.py
# 声明式：描述"想要的结果"，由引擎决定怎么做
import re, sqlite3

# 例 1：SQL —— 不写循环，数据库自己选择执行计划
con = sqlite3.connect(":memory:")
con.executescript("""
CREATE TABLE sales(region TEXT, amount INT);
INSERT INTO sales VALUES ('华东',120),('华北',80),('华东',60),('华南',200);
""")
for row in con.execute("SELECT region, SUM(amount) s FROM sales GROUP BY region ORDER BY s DESC"):
    print(row)
print("执行计划:", con.execute("EXPLAIN QUERY PLAN SELECT region, SUM(amount) FROM sales GROUP BY region").fetchall())

# 例 2：正则表达式 —— 描述"模式"，不描述匹配算法
print(re.findall(r"\b\d{3}-\d{4}\b", "电话 555-1234 和 666-9876，不是 12-34"))

# 例 3：配置即声明（类似 YAML/Docker Compose 的思想），由"执行器"负责落实
desired = {"web": 3, "worker": 2}
current = {"web": 1, "worker": 4}
plan = {svc: desired[svc] - current.get(svc, 0) for svc in desired}
print("对比期望状态得到的调整计划:", plan)
```

输出：

```text
('华南', 200)
('华东', 180)
('华北', 80)
执行计划: [(6, 0, 216, 'SCAN sales'), (8, 0, 0, 'USE TEMP B-TREE FOR GROUP BY')]
['555-1234', '666-9876']
对比期望状态得到的调整计划: {'web': 2, 'worker': -2}
```

读输出时注意 `EXPLAIN QUERY PLAN`：我们没有写“扫描表”“建临时 B 树做分组”，这是 SQLite 自己决定的执行方式。【有据可查】SQLite 对查询计划输出的解释：<https://www.sqlite.org/eqp.html>

## 常见误区

- **“声明式就不用懂底层”**：不懂底层会写出慢查询。SQL 不加索引、Pandas 里逐行 `apply`，都是“声明得很漂亮、执行得很糟”的典型。
- **“声明式一定更快”**：引擎的优化有边界，复杂逻辑硬塞进声明式 DSL（如超长正则）反而又慢又难维护。
- **把“配置文件”和“声明式”等同**：只有当存在一个“负责落实描述”的执行器时，配置才是声明式程序；纯数据文件只是数据。

## 与 AI 开发的关系

- **Polars 的 LazyFrame、Spark、DuckDB** 都靠声明式查询来做自动优化（谓词下推、列裁剪），详见 [[k1.lib.polars]]。
- **Agent 工作流 / 提示词模板**越来越多用 YAML/JSON 声明：节点、工具、输出 schema，由框架执行。【社区共识】
- **结构化输出（JSON Schema）**是声明式的：你声明“输出必须长这样”，由模型和约束解码去满足。【有据可查】OpenAI 结构化输出文档：<https://platform.openai.com/docs/guides/structured-outputs>
- **让 AI 写 SQL** 是声明式的高频场景，审查重点是语义（JOIN 条件、NULL 处理）而不是循环细节。
